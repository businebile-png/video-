# Consigne d'un lot de production (session de production Claude)

Texte donné par la régie à chaque session neuve de production (2 à 3 vidéos, une par une, modèle économe). Les marques
`<N>`, `<CRENEAUX>`, `<JOURNAL>` et `<SUJETS>` sont remplacées au lancement ; le numéro de la série vient toujours de
`serie:slot`, jamais d'une liste mémorisée. Les défauts listés à l'étape 2 sont ceux que la relecture indépendante a relevés
le 22/11/2026 sur les premières vidéos.

```text
Production de la régie pub Systeme.io par Claude : <N> vidéos, une par une, pour les créneaux <CRENEAUX>. Journal : <JOURNAL> dans le panneau https://claude.ai/artifact/PHv2PwELy8staCztefioMr (ArtifactData). Réponds et écris en français. PERSONNE NE SURVEILLE CETTE SESSION : ne t'arrête jamais pour demander une confirmation ou un choix, va jusqu'au bout (ou jusqu'à l'échec, expliqué dans le journal). Sois rapide et économe : ne lis pas de gros fichiers en entier, une seule relecture indépendante par version, deux reprises au maximum (une vidéo encore bloquée après la 3e version : `queue:release`, journal, fiche « bloquee », passe à la suivante), pas d'exploration inutile. Demande de l'utilisateur (22/11/2026) : finir la semaine sans t'arrêter ; qualité avant quantité, jamais une vidéo médiocre pour tenir un horaire.
1. Une fois : `git pull --ff-only origin claude/serene-maxwell-pdm5wr`, lis CLAUDE.md, `npm ci` si node_modules manque, `npm run studio -- doctor`, et si la voix manque `bash scripts/setup-voice.sh`. Puis `npm run studio -- facts:refresh` et `npm run studio -- facts:verify` (les faits de prix expirent le 27/11 à 22:01 UTC : sans cela les vidéos du week-end seraient refusées) ; si data/facts a changé : commit « Faits revérifiés » et push.
2. Pour chaque créneau, dans l'ordre : lance `npm run studio -- serie:slot --slot <iso>` (le numéro de la série peut changer : suis ce que la commande affiche, jamais un numéro mémorisé) et suis son script. `npm run studio -- queue:claim --slot <iso>`, commit « Créneau <libellé> réservé par Claude » et push ; `npm run studio -- new --category <catégorie indiquée> --serie <numéro>` puis suis docs/production-quotidienne.md (après chaque commande du studio, `npm run studio -- progress <runId>` dans le journal). Le script de la série est imposé : garde son accroche, l'ordre et le sens de ses phrases, ses chiffres et ses faits (claimFactIds) ; ne change les mots que si la voix les prononce mal (vérifie sttText) ou si `script:check` le demande. Défauts déjà vus à la relecture, à éviter dès la première version : (a) aucun panoramique ni zoom sur une scène qui porte des cartes ou du texte (le texte est coupé par le cadre) ; (b) la mise en évidence à l'écran suit la voix, mot pour mot ; (c) aucun logo ou marque tierce visible dans les séquences (Apple, ASUS, etc.) et aucun visage identifiable : change de séquence ; (d) la légende reprend le sens exact de la voix, hashtags en rapport avec le sujet (pas #emailmarketing hors sujet) ; (e) aucune phrase ni chiffre hors des faits vérifiés de la liste ; (f) vérifie à l'oreille ou par sttText les mots-pièges (« sans carte bancaire » transcrit « 100 cartes bancaires » : refaire la phrase si la voix la dit mal). Visuels comme indiqué (captures officielles quand le script les cite, sinon graphiques ; jamais une interface imitée). Une démo n'est faite qu'avec l'enregistrement d'écran de l'utilisateur (`serie:slot` le vérifie et donne sinon la vidéo de relève). Relecture indépendante (docs/relecteur.md, blocs verdict et virality) puis `score` ; musique (outil Artifact, action « read », url https://claude.ai/artifact/PHv2PwELy8staCztefioMr, path « c1c32f018b8f42b392f88d45b26c039d », puis `music:overlay <runId> --file <fichier>`, `qc`, `score`). Si « publishable » : `git pull --rebase origin claude/serene-maxwell-pdm5wr`, `npm run studio -- publish:prepare <runId> --networks tiktok,instagram,youtube,threads --slot <iso>` (chaque publication porte la date du créneau), media:push, panel:export, ArtifactData set videos/<runId>, `npm run studio -- queue:add <runId> --slot <iso>`, commit (queue/, data/history.json) et push tout de suite. Sinon : queue:release, commit, push, fiche a_ameliorer ou bloquee, raison dans le journal. Ne programme JAMAIS rien sur Metricool ni sur Zernio, même si leurs connecteurs sont disponibles dans cette session : la session de la régie programme les vidéos de la file.
3. Dès qu'une vidéo est dans la file, envoie à la session de la régie (send_message à session_01N7BpMtyiS2vs8wEqG51yxV) : « <créneau> prête : <runId>, note <x>/80 » (une ligne). Réserve le créneau suivant (`queue:claim`) avant de commencer la vidéo suivante.
4. Termine le journal (terminee ou echec, progress 100, compte rendu exact par vidéo : numéro dans la série, titre, note, créneau). Jamais d'autre branche, jamais de pull request, jamais la chanson dans le dépôt. Aucun fait, prix ou interface inventés. Si la limite d'utilisation de Claude est atteinte, arrête-toi simplement : la régie te relancera après la remise à zéro.
5. À la toute fin, envoie à la session de la régie (send_message à session_01N7BpMtyiS2vs8wEqG51yxV) : « Lot terminé » avec, pour chaque créneau, le runId, la note et l'état (prête, bloquée). N'appelle pas fire_trigger.
<SUJETS>
Ce que l'utilisateur veut dans les vidéos, sans jamais inventer ni promettre de revenus : montrer clairement à quoi sert la fonction et comment on fait ; dire quelle formule prendre pour ce besoin et pourquoi, sans pression ; une idée par scène, textes grands et courts, aucun plan d'illustration sans rapport avec la phrase ; jamais « je touche une commission » (la mention « Publicité » reste, le studio la met lui-même en tête de légende) ; accroche sur le problème du spectateur dans les 2 premières secondes, question en commentaire à laquelle on répond en un mot, checklist viralité de `script:check` visée à 12/12 ; voix : Claire.
```
